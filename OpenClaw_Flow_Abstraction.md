# OpenClaw 完整流程抽象：从问题到回答

本文档用**分层抽象**的方式，解释当你在 WhatsApp/钉钉问问题时，OpenClaw 内部发生了什么。

---

## 🎯 整体流程（一句话）

```
你发消息 → 网关接收 → 路由分发 → AI处理 → 工具调用 → 生成回复 → 发送给你
```

---

## 🔄 完整数据流（以"查销售额"为例）

```
时间线：

T+0ms    你在微信发消息："今天销售额多少？"
         ↓
T+50ms   微信服务器 → OpenClaw Gateway（端口18789）
         [HTTPS POST webhook]
         ↓
T+100ms  Gateway 鉴权 → 确认你是白名单用户
         ↓
T+150ms  Session Manager 加载你的历史对话
         ↓
T+200ms  构建 Context（历史10轮 + 当前消息）
         ↓
T+300ms  发给 AI（Kimi/Claude/GPT）
         [HTTP POST api.moonshot.cn]
         ↓
T+1500ms AI 推理完成：需要调用 query_database
         ↓
T+1600ms 工具层执行 SQL 查询
         [TCP 连接内部数据库]
         ↓
T+1800ms 获取结果：{sales: 150000}
         ↓
T+1900ms 结果返回给 AI，生成自然语言回复
         ↓
T+2500ms 回复发回 Gateway
         ↓
T+2600ms Gateway 调 WhatsApp API 发消息
         ↓
T+3000ms 你收到回复："今天销售额15万元..."
         ↓
T+3100ms 保存对话历史到本地文件

总耗时：约 3 秒
```

## 🎯 核心抽象概念

### 1. **Message（消息）**
所有平台的输入都抽象成统一的消息格式：
```typescript
interface Message {
  id: string;           // 消息唯一ID
  from: string;         // 发送者ID
  content: string;      // 消息内容
  channel: string;      // 来源渠道（whatsapp/wechat/dingtalk）
  timestamp: Date;      // 发送时间
  attachments?: any[];  // 附件（图片、文件等）
}
```

### 2. **Session（会话）**
维护一个用户的完整对话上下文：
```typescript
interface Session {
  key: string;          // 会话ID
  messages: Message[];  // 历史消息列表
  memory: Memory;       // 记忆数据
  state: object;        // 临时状态
}
```

### 3. **Tool（工具）**
AI可调用的功能模块：
```typescript
interface Tool {
  name: string;         // 工具名称
  description: string;  // 功能描述
  parameters: object;   // 参数定义
  execute: Function;    // 执行函数
}
```

### 4. **Agent（代理）**
处理消息的AI实体，包含：
- 系统提示词（System Prompt）
- 可用工具列表
- 记忆访问权限
- 执行策略

## 💡 关键设计思想

### 1. **分层解耦**
每层只关心自己的职责，通过标准接口通信：
- 换 AI 模型？只改第4层
- 加新通讯渠道？只改第1、7层
- 加新功能？只改第5层

### 2. **统一抽象**
无论用户从微信还是钉钉发消息，内部都是同一个 Message 对象：
```
微信消息 ──┐
           ├─→ 统一 Message ──→ 处理 ──→ 统一回复 ──→ 多渠道发送
钉钉消息 ──┘
```

### 3. **状态外置**
AI 本身是无状态的，所有状态存在 Session 和 Memory：
- 可以随时重启 AI 服务，对话不丢失
- 支持多实例部署，负载均衡

### 4. **工具即能力**
AI 的能力通过 Tool 扩展：
- 要查数据库？加 query_database 工具
- 要发邮件？加 send_email 工具
- 要操作 Excel？加 excel_tool 工具

## 🔍 故障排查视角

如果某个环节出问题，如何定位？

| 现象 | 可能出问题的层 | 排查方法 |
|------|--------------|---------|
| 收不到回复 | 第1层（网关） | 检查 Gateway 是否运行，端口是否被占 |
| 回复很慢 | 第4层（AI） | 检查 API Key 是否有效，模型是否过载 |
| 查不到数据 | 第5层（工具） | 检查数据库连接，SQL 是否正确 |
| 回复格式乱 | 第6层（生成） | 检查 Prompt 是否正确，格式模板 |
| 发不出去 | 第7层（输出） | 检查微信/钉钉 API Token 是否过期 |
| 历史丢失 | 第8层（存储） | 检查磁盘空间，文件权限 |

## 📚 总结：三层记忆

记住这个简化版：

```
┌───────────────────────────────────────┐
│  接入层：Gateway（接收/发送消息）       │
├───────────────────────────────────────┤
│  智能层：AI + Tools（理解+执行）        │
├───────────────────────────────────────┤
│  数据层：Session + Memory（记忆）       │
└───────────────────────────────────────┘
```

**流程口诀**：
1. **收** - Gateway 收消息
2. **记** - Session 加载历史
3. **想** - AI 理解意图
4. **做** - Tool 执行操作
5. **说** - AI 生成回复
6. **发** - Gateway 发回去
7. **存** - 保存到硬盘
